SEO LEARNING / PRACTICAL CHECKLIST

Learn SEO on a
real, useful site.

You can practise technical and on-page SEO without buying a custom domain. Deploy this static portfolio to Vercel and use the free production URL it gives you. Search engines need a public URL to crawl; a local file or localhost preview is for learning and testing, not indexing.

Deploy with Vercel ↗
01 / GO LIVE

Start with the free deployment URL

Publish the static site

Import this repository into Vercel, keep the project root at the repository root, and deploy. This project has no package manifest or build step: its HTML files and assets are served as static files. Use the production URL Vercel assigns, usually ending in .vercel.app.

Confirm the live homepage, /about.html, /projects.html, /seo-practice.html, and /pages/ai_mockinterview.html load over HTTPS before adding the site to Search Console.

Use the production URL as your temporary site address

The canonical links in these pages use root-relative paths, so the production host supplies the origin. Do not replace these with localhost, a preview deployment URL, or a made-up domain. If you later connect a custom domain, keep one preferred host and redirect the alternate host to it.

02 / SITEMAP

Generate a sitemap after deployment

A sitemap must list absolute public URLs. Since your Vercel production URL is not known in the source yet, this project does not ship a sitemap full of placeholder addresses. After deployment, run this from the repository root in PowerShell, replacing the example URL with your actual production URL: 

.\scripts\generate-sitemap.ps1 -SiteUrl "https://your-project.vercel.app"

The script writes sitemap.xml with the five intended content pages and adds its absolute URL to robots.txt. Check its URLs, commit both files, redeploy, then check that https://your-project.vercel.app/sitemap.xml loads. Update the script if you add or remove a page.

Robots and sitemap are different

robots.txt allows crawlers to access this public site. It does not guarantee indexing or prevent a URL from appearing in search. The sitemap generator adds the sitemap URL to robots.txt. Submit the sitemap in Search Console after the generated file is deployed. Do not block pages that you want crawlers to read.

03 / MEASURE

Practise with Search Console

  1. Open Google Search Console and add the deployed HTTPS address as a URL-prefix property.
  2. Complete the available ownership verification method. A custom domain is not required for a URL-prefix property.
  3. Submit the sitemap URL after it is live, then inspect the homepage and one inner page.
  4. Review indexing status, selected canonical, mobile usability, and any enhancement reports that apply.
  5. Make one useful improvement at a time and compare impressions, clicks, and queries over several weeks.

Indexing and ranking are not guaranteed. A newly deployed site may take time to be discovered and evaluated.

04 / WRITE FOR PEOPLE

Grow the site with genuine detail

Good next pages

Add a case study only when you can explain a real project: the purpose, your contribution, tools used, decisions made, and what you learned. Add process images or outcomes only when they are your own and you can accurately describe them.

Keep a page only if it answers a distinct visitor question. Do not create repeated city pages, keyword variants, empty category pages, fake testimonials, or fabricated client results just to increase page count.

White-hat checklist

  • One clear page topic, useful title, concise description, and one main heading.
  • Descriptive internal links that accurately name their destination.
  • Original text and accurate image alternatives; no keyword stuffing.
  • Fast, mobile-friendly pages with working navigation and HTTPS.
  • Earn relevant links by sharing genuine work; do not buy or automate links.
  • Refresh or remove obsolete content instead of creating thin duplicates.
